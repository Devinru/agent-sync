# 适配器契约

每个接入的端实现一个适配器：**把自己的原生记忆翻译成共享格式，再把共享格式翻译回自己的记忆。**

**双向是硬要求。** 只导出不导入 = 只做了一半；只导入不导出 = 只会接收。

---

## 六个接口

```python
class Adapter:
    def inspect(self, config: dict) -> dict:
        """只读：我的环境是什么样。
        返回：客户端版本、profile、原生记忆路径、有效容量、可用能力、阻塞原因。
        """

    def snapshot_native(self, cursor: str | None) -> dict:
        """只读：把我本地的记忆导出成候选列表。
        cursor 是上次同步的位置，为 None 表示全量。
        返回：每条的 {native_id, title, body, kind, status, content_hash, ...}
        """

    def propose_export(self, native: dict, shared: dict, mapping: dict) -> dict:
        """纯计划：本地有什么要推上去。
        必须给出新增/修改/退役建议 + 依据 + 对应本地记录。
        不许在这里提交 git 或改原生记忆。
        """

    def plan_import(self, records: list[dict], native: dict, mapping: dict) -> dict:
        """纯计划：共享的记录要怎么落进本地。
        必须给出每条的目标位置、转换后内容、预期旧值、冲突。
        """

    def apply_import(self, plan: dict, authorization: dict) -> dict:
        """真写：按计划改本地记忆。
        必须能回滚（写前备份），必须幂等（重跑不重复追加）。
        """

    def verify_import(self, result: dict) -> dict:
        """只读：写完之后，本地真的能用了吗。
        要读回来，要能检索到。不能只看文件存在。
        """
```

## 能力声明

适配器要诚实声明自己支持什么，写进 `adapters/<端>/manifest.json`：

```json
{
  "adapter_id": "hermes-linux",
  "adapter_version": "0.1.0",
  "protocol_major": 2,
  "framework": "hermes",
  "supported_os": ["linux"],
  "tested_client_versions": ["v0.21.0"],
  "implementation_status": "verified",
  "capabilities": {
    "export_native": true,
    "plan_import": true,
    "apply_import": true,
    "verify_native_recall": true,
    "preserve_provenance": true,
    "retire_imported_record": true
  },
  "guide": "guides/hermes.md"
}
```

**`implementation_status` 三档**：

- `verified` — 跑过完整往返，有证据
- `partial` — 只能做一部分，写清楚哪部分
- `planned` — 只有设计，代码没写

**不许把 `planned` 写成 `verified`。**

## 转译必须保留的东西

翻译可以改措辞，不能丢这些：

1. **事实 vs 推断**（`epistemic`）
2. **谁说的**（`origin` / `evidence`）
3. **因果关系**（为什么会这样）
4. **适用条件**（在什么情况下成立）
5. **时间限制**（什么时候的事、什么时候失效）
6. **目标句**（topic 的 `goal`）
7. **明确禁令**（不许做什么）
8. **退役状态**（这条已经作废了）

**如果你只能存摘要**：完整正文放你的长期层，常驻摘要指向它。读回验证时两个都要在。

**如果你判断不了转译有没有丢东西**：返回 `needs_review`，给出原文和你的拟写对照，让人看。**不许自己觉得「意思差不多」就替换。**

## 三方比较

同步时每个人的状态都不一样。用四个值判断：

- **B** = 上次成功同步时的共享版本（基线）
- **S** = 现在共享仓库里的版本
- **L0** = 上次成功同步时的本地版本（基线）
- **L** = 现在本地版本

| S vs B | L vs L0 | 怎么办 |
|---|---|---|
| 未变 | 未变 | 什么都不做 |
| 变了 | 未变 | 拉下来，导入 |
| 未变 | 变了 | 本地有新东西，提案推上去 |
| 变了 | 变了 | **冲突**，两边都留着给人看 |
| 新记录 | 无映射 | 新导入，先查有没有语义重复 |
| 远端退役 | 本地未变 | 本地标记 dormant |
| 远端退役 | 本地有新内容 | 只退可精确定位的部分，定位不了就停下 |

**不许用「谁的时间戳更新」判断谁对。** 跨机器时钟不可靠。

## 防回声（最容易踩的坑）

**问题**：导入一条记录 → 下次导出时又把它当新记录推上去 → 无限循环。

**解法**：

1. 导入时写一条映射：`shared_id → native_id` + 双方的内容 hash
2. 下次导出前，先比对「本地现在的内容」vs「导入时记下的 hash」
3. 没变 → 不提案
4. 只有措辞变了、意思没变 → 更新映射里的 hash，不产生新记录
5. 真的变了 → 才有提案

**同一来源重复 10 次，evidence 仍算 1 条。** 导入本身不算新经历。

## 去重（你的适配器必须实现）

**判重不是可选项。** 不做去重，共享仓库几周内就会堆满同一件事的十几个版本。

### 你的导出接口要做的

```python
def propose_export(self, native, shared, mapping):
    # 1. 先算：本地新增的，和 shared 里所有记录比一遍
    # 2. 相似度超过阈值 → 不要用 create，改成 update（合并进已有那条）
    # 3. 把「打算合并进哪条 + 依据」写进提案
```

**别只比映射表里对应的那条。** 映射只记「这条是从哪来的」，判重要找的是「有没有另一条讲同一件事」。

### 你的导入接口要做的

```python
def plan_import(self, records, native, mapping):
    # 1. 远端每条，和本地所有记录比一遍
    # 2. 相似度超阈值 → 标成 possible_duplicate，别静默新建
    # 3. 冲突的那几条列出来给人看
```

### 筛选算法（可以照抄，也可以换，但要有可测的阈值）

| 信号 | 权重 |
|---|---|
| 同名标识（`USER.md`、`renpy`、`ComfyUI`） | 0.35 |
| 正文双字 Jaccard | 0.30 |
| 中文三字重合 | 0.20 |
| 标题相似（前缀包含给 0.92） | 0.15 |

综合分 ≥ 0.25 进候选。

**中文场景的坑**：默认分词器会把整段中文当一个词。要么用 trigram，要么自己做双字/三字切片。

**阈值宁可压低。** 漏掉真重复的代价，远大于多看几对假候选——假候选模型一眼能否掉，真重复会一直烂在库里。

### 判定交给模型，但必须留痕

每次判定记一笔：

```
哪天 把哪条当成哪条的重复
依据是什么（哪几句/哪个标识重合）
被合并的那条独有信息去哪了
```

**不能是「模型觉得重复就没了」。** 人得能查回来。

### soul / rule 例外

`kind` 是 `soul` 或 `rule` 的记录，**在筛选阶段就排除**，不进任何自动合并流程。

它们只能：
- 报差异
- 出提案给人逐条看

理由不是「重要」，是：**模型判断人格设定重不重复，等于模型决定这个 agent 是谁。**

---

## 一条重要的边界

**不要为了让自己的端好接，去改公共协议。**

协议是大家的。你的端做不到，就在自己的指南里写 `unsupported`，提一个「协议能否支持」的提案让人决定——**不能自己把规矩改松**。

同理，**不许绕过宿主的记忆管理接口直接改文件**。产品只允许通过特定入口维护记忆，就得走那个入口。
