# 生命周期

一条记忆从产生到退役，经过这几步。每一步都有明确的规则，不靠感觉。

---

## 沉淀

**不是所有东西都值得进共享仓库。** 入口就把关。

### 什么该记

**如果别的端不知道这条，会不会重复问、重复做、或者给出矛盾的建议？**

会 → 记。不会 → 不记。

### 三类东西，三个去处

| 长什么样 | 去哪 | 判据 |
|---|---|---|
| 一句话说完的事实、偏好、规矩 | 直接进该端的常驻记忆 | 没有过程 |
| 有先后、有因果、有经过的 | 本仓库 `memory/records/` | 拆开有过程 |
| 某个项目的完整上下文 | `memory/records/` + kind=project | 只做这个项目时才有用 |

---

## 深度

| depth | 意思 | 什么时候升 |
|---|---|---|
| `recent` | 刚沉淀，还没验证 | 默认 |
| `stable` | 反复出现，或被确认 | 见下 |
| `core` | 人格核心，只允许 soul/rule | 人工确认 |

### 升到 stable 的条件（满足任一）

1. 用户明确要求长期记住，且来源可定位
2. 重要的一次性经历，经用户确认了它的意义
3. 至少两份独立经历支持同一结论，且没有未处理的反例
4. 有持续用途的、已验证的环境事实（必须写清适用范围）

**`epistemic: inferred` 升到 stable 后仍然是 `inferred`。** 深度变了不代表它是事实了。

---

## 复核

**复核不是删除。** 到期只是提醒该看一眼。

| 类型 | 周期 |
|---|---|
| episode / reflection / topic | **60 天** |
| fact / preference / lesson / project | **120 天** |
| soul / rule / core | **不自动复核** |
| `review_after: null` | 不设期限 |

**到期时的动作**：

- 有新的证据支持 → 保持 `active`，更新 `review_after`
- 已结束且无持续用途 → 转 `dormant`
- 被证明错了 → 走「更正」
- **拿不准 → 保持原样，写一句「未获得新证据」**

**不许因为「到期了」就自动沉底。** 60 天没人提，不代表它不重要。

---

## 更正

**更正不是覆盖，是新的记录取代旧的。**

```yaml
# 新记录
supersedes: ["<旧记录 id>"]

# 旧记录
status: superseded
```

规则：

1. 旧记录**保留**，状态改成 `superseded`
2. 新记录的 `supersedes` 指向旧 ID
3. 两条要在**同一次提交**里改（依赖组）
4. 普通回忆默认不返回 `superseded`，但可以显式查

**如果只是补充，不是推翻**：改原记录，`revision + 1`，不需要新建。

---

## 合并

两条记录讲的是同一件事：

1. 选一个保留（通常选信息量大的那个）
2. 另一条设 `superseded`，它的 `related_ids` 被新记录继承
3. 新记录写 `related_ids` 指向被合并的
4. 一次提交改完

**不许静默删文件。** 删了 ID 就没了，别的端下次同步又把它建出来。

---

## 退役

| status | 意思 | 普通回忆返回吗 |
|---|---|---|
| `active` | 正常 | 是 |
| `dormant` | 不常驻，但仍存在 | 是（标记为低活跃） |
| `superseded` | 被新记录取代 | 否 |
| `retracted` | 撤回 | 否 |

**退役保留 ID。** 这是为了防止「本地删了 → 下次同步又从远端拉回来」。

### 撤回 vs 删除

- **撤回**（`retracted`）：不再使用，但 git 历史里有。**这是默认动作。**
- **删除**：需要单独授权。即使删了文件，git 历史、其他克隆、备份里可能还有。**不许声称「彻底删除」除非真的清了所有副本。**

---

## 防自我强化

这几件事**都不算新证据**：

- 自动扫描发现了它
- 我自己检索到了它
- 另一个端导入了它
- 重复了 10 次

**只有真实发生的新事件才算新证据。**

`recall_count` 这类统计可以有，但**不能用来提升可信度**。

---

## 人格核心

`soul` / `rule` 是特殊层：

1. **不许自动写入**，任何自动流程只能生成提案
2. 改它要**单独展示差异**：旧文是什么、新文是什么、为什么改
3. 用户对「普通记忆同步」的泛泛确认，**不能替代**对人格修改的确认
4. 写之前算 hash，写完再算一遍，不一致就回滚

**普通记忆的深度晋升，不自动改人格。** 这是两件事。
